# NEXORA Individual Growth Engine Audit

Date: 2026-07-28  
Scope: existing production Next.js/Airtable website and growth operations codebase.

## Current System Shape

- Frontend/backend framework: Next.js 15 App Router, TypeScript, React 19, Tailwind CSS, Framer Motion, lucide-react.
- Database/CRM: Airtable is the operational source of truth through `src/lib/airtable.ts`.
- Authentication: no first-class user auth. Admin routes use `GROWTH_ADMIN_SECRET`, `TELEGRAM_QUEUE_SECRET`, or `CRON_SECRET`. Associate portal uses referral-code lookup.
- Deployment: Render web service plus a Render cron blueprint in `render.yaml`.
- Integrations: Airtable, Paystack, Resend, Telegram, Calendly, Apify.
- Tests: no dedicated test runner; verification is currently `npm run typecheck` and `npm run build`.

## Current Associate Lifecycle

Current implemented flow:

```text
Public application
-> Ambassador Registrations record
-> Admin dashboard review
-> Schedule Interview action
-> Calendly/email invite
-> Pass Interview action
-> Ambassadors record created
-> Referral Code and Referral Link created
-> Associate portal available by referral code
```

The Growth Associate admin route is `src/app/api/growth-associate/admin/route.ts`. The current action that creates an official associate is `Interview Passed`. The helper `createOfficialAssociate` creates the `Ambassadors` record and stores:

- `Referral Code`
- `Ambassador Referral Link`
- `Referral Link`
- `Ambassador Status = Active`
- `Active = true`
- `Daily Lead Quota = 10`
- `Monthly Intake Target = 30`
- `Onboarding Status = Invited`
- `Referral Status = Active`

## Current Referral Logic

- Referral code format is generated by `codeFromName` in `src/lib/growth-associate.ts`.
- Current format: `NEX-[NAME PREFIX]-[RECORD SUFFIX]`.
- Referral link format: `https://www.nexoragroup.ink/career-accelerator?ref=CODE`.
- Referral code generation currently depends on the recruitment action that creates an `Ambassadors` record.
- Existing referral codes are stored on `Ambassadors`.
- Payment attribution uses `referralCode` through website forms, Paystack metadata, `Website Payment Events`, `Ambassador Referrals`, `Referral Events`, and `Conversion Attribution`.
- Existing codes must be preserved. The new rule should assure missing codes for approved/active associates without regenerating working codes.

## Existing Associate Inconsistencies To Detect

The system can currently contain:

- Active/approved associates missing `Referral Code`.
- Associates with `Referral Code` but no `Referral Link`.
- Active associates missing email, phone, or Telegram User ID.
- Associates whose interview/registration link is missing because they were added manually.
- Duplicate emails, phones, or referral codes in `Ambassadors`.
- Conflicting status values across `Ambassador Status`, `Active`, `Onboarding Status`, and `Referral Status`.

## Existing Lead Implementation

Existing lead operations are centered on `Growth Leads` and `Lead Activities`.

Current capabilities:

- Growth lead table extension script exists: `scripts/sync-growth-operations-airtable.mjs`.
- Lead assignment exists in `src/lib/growth-actions.ts`.
- Assignment currently can distribute any available Growth Lead.
- Activity log exists via `recordLeadActivity`.
- Associate portal can show assigned leads and update lead status.
- Daily automation exists and previously focused on business leads via Apify.

Current gaps for this prompt:

- No individual-only allocation guard.
- Business lead discovery is still present in the admin and automation code.
- No batch-completion threshold.
- No explicit allocation eligibility reason.
- No idempotent referral repair service.
- No system-health endpoint for missing referral IDs.

## Existing Integrations

- Airtable: `listRecords`, `createRecord`, `updateRecord`.
- Paystack: initialization route creates contacts/applications/payment events and passes referral metadata. Webhook verifies payments and attribution.
- Telegram: admin notifications and associate lead activity commands.
- Resend: recruitment emails.
- Calendly: interview scheduling webhook.
- Apify: lead discovery currently creates `BUSINESS_TRANSFORMATION` Growth Leads.

## Integration Recommendation

Recommended approach: **C. Add a compatibility layer around existing models.**

Reason:

- Airtable is already live and contains production data.
- Existing applicant, associate, payment, referral, and lead records must be preserved.
- The safest path is additive: create shared services for status normalization, referral assurance, health checks, and individual allocation while reusing `Ambassadors`, `Growth Leads`, `Lead Activities`, and `Growth Audit Logs`.
- Future SME/corporate engines can remain in code behind feature flags, but Version 1 active assignment should use only individual Career Accelerator leads.
